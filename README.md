# 社区课程报名对照实验

祥和里社区教育合作社的课程团队用这本试验簿比较邀请文案，依次锁定方案和名单、观察报名与到课、计算并签署复盘结论。

合作社的 8 名固定工作人员协调 3 个社区教学点，平时在共享表里保存名单，在工作群记录临时换课，再把纸质签到簿转录成表格。统计常遇到三个问题：发错邀请后覆盖了原组，空白签到被当成未报名，课程结束后才决定用报名率还是到课率。工作台接收已核验的匿名居民编号和签到凭证，把锁定的分组、口径及复核快照交给下期课程排班负责人。

## 业务模块

| 模块 | 实际操作 |
|---|---|
| 课程方案 | 固定课程、两种邀请方式、主指标及时间窗，由督导检查后锁定 |
| 分组前资格预审 | 统筹提交匿名名单及凭证，督导批准或退回。退回后保留旧版，分组只接受最新获批版本 |
| 随机分组 | 导入匿名居民编号，以约 1:1 随机分配，保存种子和名单摘要；可记录观测前的资格剔除 |
| 课程邀请送达核对 | 按真实邀请组批量登记送达回执，追踪失败和重试；未送达居民暂不能登记观测 |
| 讲师与场次容量 | 统筹核对讲师占时、带班上限与教室容量，在签到名册锁定前调整开放席位 |
| 席位与候补 | 受理原始名单居民报名，满额进入跨组 FIFO 候补，撤回或扩容时自动递补 |
| 签到与观测交接 | 本场讲师锁定确认名册并签署到课及缺席，观测员核对全部居民后写入原分组观测 |
| 报名观测 | 从签到交接接收结果，或在未排课实验逐人登记；名单完整且窗口结束后提交分析 |
| 报名观测更正复核 | 观测员提交更正凭证，督导批准后才更新结果。待复核时暂停封存 |
| 复盘审批 | 对照两组分子和分母、p 值、百分点差、区间及效应量；签署批准或驳回，批准后下载 JSON |

## 启动

```bash
cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

打开 `http://localhost:18242`。FastAPI 接口和 OpenAPI 文档位于 `http://localhost:19242` 和 `http://localhost:19242/docs`，PostgreSQL 暴露端口 `17742`。通过前端访问的 API 统一使用 `/api/` 前缀。关闭服务可执行 `docker compose down`，需要删除本实例全部测试数据时可加 `-v --remove-orphans`。

2. 09:00，陆宁检查 11 月 14–20 日的观测窗口与居民报名率口径，锁定每组至少 12 人。
3. 09:15，林嘉将 `ZH-001` 至 `ZH-048` 导入，一次分出 24/24。该步骤已写入种子。
4. 10:00，周葵依据 `拓印课签到簿_1120.csv` 核对系统里已有的 32 条记录。观测页显示每组仍缺 8 条，并在名单齐前保留封存限制。
5. 10:30，按签到簿补录剩余 16 条。要复现浏览器验收中的计算值，可依 `test-artifacts/gb-1043/tests/e2e.cjs` 建立示例「旧物修补开放课」并登记 A 组 8 人、B 组 18 人报名。

8. 14:00，在另一档「手机摄影散步」中确认收错邀请，周葵登记实际邀请，系统保留原组并冻结，陆宁签署驳回。

## 带资格预审的实验

`CC-1119`「居民香草栽培课」预置了 24 位匿名居民的待审名单，凭证为 `花圃课资格核对_1114.csv`。先用督导账号退回或审批名单，再用课程统筹账号分组并登记送达回执。可以为一位居民记录短信失败，再用电话完成补送。观测员登记报名或到课后，可提交签到复核凭证给督导，签署通过后再提交统计检验。

- 方案检查通过后，统筹提交第一版名单即启用本流程。已有名单预审记录的实验始终受这些规则约束。升级前的实验及未提交名单预审的实验可继续使用原流程。
- 送达凭证按居民留存。每批只接受同一原始分组的有效居民，尝试日期须在锁定观测窗口内且不能晚于当天。失败可按时间顺序补记新的回执，首次成功回执随后锁定。错组应走「随机分组」页已有的改组上报与冻结流程。
- 受控实验已登记的结果通过更正单修改。同一居民同时只允许一张待审单。退回时保留原结果及意见，通过时写入更正凭证及观测日期。每位有效居民均有送达和观测结果、且无待复核更正，才可封存。

## 从排课跟进到签到交接

`CC-1122`「冬日阳台育苗课」已预置 32 个匿名居民编号，按 A/B 各 16 人随机分配。在「场次容量」用统筹账号为唐雯登记 11 月 20 日 09:00–10:30 的课，带班上限 16 人，教室上限 14 人，先开放 10 席。与同一讲师的已有场次有重叠，或超出任一上限时，系统拒绝保存。

1. 在「席位候补」录入 14 条报名。席位不足时按**系统受理顺序**排队，报名日期与凭证保留在各自记录中。纸质材料允许按发生日期补录至讲师锁定名册。
2. 登记一位已确认居民来电撤回，列表保留原报名及撤回凭证，队首补入。以 `追加两张育苗操作台_1120.csv` 将开放席位从 10 增至 12，再补入 2 人，余下 1 人继续候补。
3. 本场讲师在开课后锁定确认名册，下课后按 `育苗课讲师签到簿_1120.csv` 提交覆盖所有 12 个确认席位的签到表。观测员核对预览及凭证后，一次写入原名单的 32 条结果。
4. 有资格预审的实验仍需邀请成功回执。报名日期须在送达当日或以后，交接时每位有效居民均需不晚于上课日的成功回执。缺回执会保留讲师已签署的签到表并阻止整批交接，补齐后可重试。
5. 交接后从「报名观测」封存，督导在「复盘审批」签署并下载统计快照。原始分配、资格和分母贯穿席位及签到步骤。

每个实验可选用一个场次。排课后，结果由签到交接登记，签到签署与交接均保留操作人和凭证。当场次已锁定，席位和候补记录进入只读。尚未安排场次的实验继续沿用独立观测和更正流程。

## 指标与计算

- 报名率 =（已到课＋已报名未到课＋候补未获席＋报名后撤回）÷ 本组有效原始分配人数。到课率 = 已到课 ÷ 同一分母。仅用预先锁定的主指标做检验。待登记会阻止分析，明确未报名则在分母内。
- 先随机分配，若后来确认存在资格误录，只能在排课及任何观测开始前登记剔除，原始分配保留。有效人数低于指定每组下限，或组比超出 45%–55%，立即冻结。分析审批前报告错组也会冻结，冻结结果只能驳回。
- Python 计算双侧两比例 Z 检验，合并比例计算标准误，α 固定为 0.05。由 `B − A` 计算百分点差、Newcombe–Wilson 95% 区间和带方向的 Cohen’s h。零假设下任一期望格数少于 5 时冻结。
- 分组复现使用已保存的 128 位种子，以 `SHA-256(seed:居民编号)` 排序后交替分配，再以名单摘要核对导入名单。复盘输入摘要绑定方案编号、主指标、名单摘要与封存观测；批准快照包含聚合数据和输入摘要。

## 代码与本地开发

| 目录或组件 | 职责 |
|---|---|
| `frontend/index.html`、`styles.css`、`src/` | Nginx 服务原生 HTML/CSS 与 ES modules，各页共享档案导航、状态标记、分组摘要和审核流水 |
| `backend/src/app.py`、`auth.py`、`contracts.py` | FastAPI 路由、JWT、校验、错误处理和请求追踪 |
| `backend/src/workflow.py`、`migrations/` | PostgreSQL 领域模型、阶段校验、事务和审计事件 |
| `backend/src/control_contracts.py`、`control_records.py`、`controls.py` | 资格、送达、更正契约和业务校验，由分组、观测与封存事务调用 |
| `backend/src/worker.py`、`statistics.py` | Redis 唤醒，PostgreSQL 队列与恢复，分析快照在后端与 worker 共享卷生成 |
| `backend/src/class_schedule.py`、`seat_queue.py`、`attendance_handoff.py` | 讲师排期校验、受理与递补事务、签到与观测交接 |
| `backend/src/session_routes.py`、`session_ledger.py`、`session_contracts.py` | 场次读写接口、同一数据库快照中的席位与签到投影、数据契约 |
| `backend/scripts/seed_demo.py`、`seed_course_session.py` | 五个账号、五份方案、两份已分组名单、部分观测及一份 24 人待审资格名单 |

前端可修改 ES modules 后执行 `docker compose up -d --build --wait frontend`。本机调试后端可使用 Python 3.11 虚拟环境安装 `backend/requirements.txt`，从 `backend/` 启动 `uvicorn src.app:app --reload`。需准备 PostgreSQL、Redis 和可写的 `/analysis`，并提供 `PGHOST`、`PGPORT`、`PGDATABASE`、`PGUSER`、`PGPASSWORD`、`REDIS_URL` 与 `JWT_SECRET`。

Compose 使用 `COMPOSE_PROJECT_NAME`、`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT`、`DB_PASSWORD`、`JWT_SECRET` 和 `SEED_DEMO`，默认值见 `.env.example`。五个服务各自执行健康检查；PostgreSQL、Redis 和分析快照分别使用命名卷。演示默认值适用于本机环境。

共享枚举见后端 `src/contracts.py`、数据库迁移约束及前端 `src/view.js`。角色用于 `src/auth.py`、`src/app.py` 和各页操作权限，方案阶段用于 `src/workflow.py`、`src/worker.py` 和各页状态与表单，观测结果用于 `src/workflow.py` 与 `src/observations.js`，主指标用于 `src/worker.py`、`src/plan.js` 与 `src/review.js`。分组和复核状态同时出现在 SQL 约束、输入输出契约及对应业务页面。

预审与更正状态、送达结果和渠道在 `src/control_contracts.py`、`migrations/002_experiment_controls.sql` 和 `frontend/src/controls.js` 同步。资格摘要字段由 `src/contracts.py` 输出，`roster.js` 和 `observations.js` 读取。

场次阶段、席位状态与签到标记见 `backend/src/session_contracts.py`、`session_policy.py`、`seat_queue.py`、`migrations/003_course_session.sql` 至 `005_attendance_handoff.sql`，以及 `frontend/src/session-actions.js`、`waitlist.js`、`attendance.js`。
